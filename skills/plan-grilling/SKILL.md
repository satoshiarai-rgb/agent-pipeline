# 計画を詰める

**決まっていないことを残したまま計画を書かない。** 前提が固まっていない計画は、実装中に
誰も見ていないところで判断が埋まる。

**自分で答えを決めてはいけない。** 問いを立てた本人が裁くと、前提の偏りが誰にも見られないまま
計画に入る。あなたの推奨は問いに添える材料であって、採る根拠にはならない。

| 種類 | 例 | 扱い |
|---|---|---|
| **事実** | どこに何があるか、既存の書き方、呼び出し元、同じ型の既存物 | `researcher` に調べさせる。問いにしない |
| **決定** | 語の解釈、範囲の切り方、作りの選択。複数の読み方・作り方がありうるもの | 問いにして観点の 2 人に渡す。自分では採らない |

## 事実を調べる（`researcher` に任せる）

**あなたはリポジトリのファイルを開かない。** あなたが読んだ中身はあなたの長い履歴に残り、以降の
ターンのたびに送り直される（実測で、本体が 71 回読んで cache read が 10.6M に膨らんだ）。
`researcher` が読んだものは、その短い履歴の中で 1 回だけ課金されて消える。

- 問いは**まとめて 1 回で**、前景の `Task`（`run_in_background: false`）で渡す。足りなければ、
  もう一度 `Task` で起こして聞く（`SendMessage` で継続しない。答えを待つ手段が無く、空打ちでターンを
  使う — `agent-pipeline:shared-team` の「呼び方」と同じ理由）
- 返ってくるのは事実とパス・行番号だけで、判断は含まれない。判断が要るものは次の問いにする
- **同じ型の既存物は全部挙げさせる。** 1 つだけ見て「ここだけ違う」と書いた計画が差し戻された

## 問いを立てて答えさせる

設計は**木**として見る。ある決定の下には、それが決まってはじめて意味を持つ決定がぶら下がる。
いま問えるのは**前提がすでに片付いた決定**（frontier）だけである。

1. 決めるべきことを木として書き出す
2. frontier を 1 ラウンド分の問いにまとめる
   - 見出しは `## Q<n>: <問いの見出し>`。本文に問いと選択肢を書き、**各問いに推奨答を添える**
     （`**推奨**: <推すもの。理由は 1 行>`）
   - 他の問いの答えに依存する問いは次のラウンドに回す。判断の記録で片付いた決定は問い直さない
3. **すべての問いを、観点の 2 人に同じ内容で、並列に 1 回で**渡す（呼び方は `agent-pipeline:shared-team`）。
   どちらの観点の問いかをあなたが振り分けない（振り分けると、下の表に無い「片方にしか聞いていない」
   状態ができる）。**2 人の答えがそろうまで次に進まない**
4. **答えがそろったら、その場で記録を書く**（判断の記録は `agent-pipeline:shared-journal`、やり取りの
   記録は `agent-pipeline:shared-team`。最後にまとめて書くと、途中で止まったときに片付いた決定が失われる）
5. frontier を再計算し、空になるまで 2〜4 を繰り返す。**ラウンドは 3 回まで**

## 答えの合わせ方

2 人の答えは、問いごとに次の表で扱いを決める。**表に無い判断をあなたが足さない。**

| 2 人の答え | 扱い |
|---|---|
| 同じ答え | 採る（`status: adopted`） |
| 片方が根拠つきで答え、もう片方は「観点外」か「未確認」 | 根拠つきの答えを採る |
| 食い違う（どちらも根拠つきで、答えが違う） | 「割れた」。採らずに `status: open` |
| どちらも「未確認」か「観点外」 | 「未確認」。採らずに `status: open` |
| 3 ラウンドで片付かなかった | `status: open` |

- `status: open` の問いは**あなたの推奨で埋めずに**、計画の「前提」の未確認に残す（人間が承認の
  ときに決める）
- **「割れた」の片方が事実の誤りに基づくと分かったら**、`researcher` に確かめさせ、事実を添えて
  同じ問いを次のラウンドで問い直す（誤った前提のまま人間に渡すと、決定も誤る）

## 往復しなくてよいとき

**frontier が最初から空なら、往復は 0 回でよい。** 判断の軸は issue の詳しさではなく、決めるべきことが
残っているか。issue が細かくても、**既存実装の事情で決めることは残る**（既存の仕組みとの衝突、
テストの空白、消えるカバレッジ）。
